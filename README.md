# BSP-Mod Fixes

Fixes for other mods in the Build Secure Protect (BSP) modpack: Minecraft 1.20.1, Forge 47.4.x. MIT.

The mod patches bugs and exploits in **Numina 2.3.13** and **Modular Powersuits 2.3.13** without shipping or changing their jars: mixins into their classes, event handlers of this mod's own, and language files that fill the gaps in theirs. It is installed on every client and every server, and it requires exactly the versions it was built against, so a different Numina or Powersuits refuses to start instead of being patched wrongly.

It also patches **EMI 1.1.24+1.20.1+forge**'s JEI compatibility layer: so that Tinkers' Construct 3.12.1.231 recipes render in EMI, so that a shaped crafting recipe with fewer than nine inputs no longer crashes the game when viewed with a JEI transfer screen open, and so that JEI's own recipe transfer handlers no longer fail on EMI's slot views from a machine's screen. EMI is optional and client-side: those fixes apply only when exactly that EMI build is loaded, and any other EMI (or none) costs them and nothing else, with one line in the log.

And it patches two spots of **Minecraft 1.20.1** itself for the pack's Velocity network, where players switch servers with Forge Client Reset Packet: a packet queued just before the switch changed the connection's protocol no longer closes the connection, and a disconnected screen is only ever opened on the render thread. Mixins into Minecraft classes are remapped for production; the one into a client-only class is skipped on dedicated servers.

It also patches **Modular Powersuits** twice more: for a value it leaves on the player (the creative flying speed its Glider, Sprint Assist and Jump Assist modules change and never restore) and for its HUD energy meter, which showed for any mod's energy-storing armor; and **AdvancedAE 1.3.6-1.20.1**'s quantum armor so its damage absorption shows on a suit readout. AdvancedAE is optional, on both sides: that fix applies only when exactly that build is loaded and is skipped with one line in the log otherwise.

And it patches **Gobber 2 2.8.9**'s dragon armour, whose creative flight flickered and would not hold on a server because the armour sent the player's abilities every tick from both sides. Gobber is optional, on both sides, gated to exactly that build, and the fix has a switch in the server config for the day Gobber fixes it itself.

And it patches **Compact Machines 6.0.3**, which saved its whole room dimension to disk on the server thread every time a machine block loaded, and kept every room with a tunnel loaded for good; and whose room preview kept its video and native memory after closing and gave any player any room's full contents on every click. Optional, on both sides, gated to exactly that build, with a switch in the server config.
And it patches **MFFS (Modular Force Field System) 5.1.29**: its sponge module, which copied, shuffled and walked every position inside the force field every three seconds and loaded chunks on the way, so a large field stalled the server on every pass; its projector, which put no bound on a field's size; and its force field blocks, each of which asked the server for its data one by one as its chunk arrived, so a field of twenty chunks' radius froze players' clients. Optional, on both sides, gated to exactly that build, with switches and limits in the server config.

And it patches **Deep Resonance 1.20-5.0.6**'s radiation shielding handler, which read the level from the entity that placed a block and crashed on a block placed by no entity, which is what Ballistix blast debris is when the blast had no owner. Optional, on both sides, gated to exactly that build, with a switch in the server config.

And it patches **Iron Furnaces 4.1.8**'s per-player furnace list, which its capability appended to instead of replacing whenever it loaded, so that a second load of a player (BSP-InventorySync's restore at login) doubled the list on every login; one player's file reached two million entries for two furnaces. Optional, on both sides, gated to exactly that build, with a switch and a warning cap in the server config.

And it patches **Voltaic 1.20.1-1.2.2**, the library that runs Nuclear Science's radiation, which shielded a dose by the four armour slots only, so Evolved Mekanism's Portable Hazmat Suit in its Curios slot protected against Mekanism's radiation and not Nuclear Science's. Optional, on both sides, gated to exactly that build with Mekanism and Curios present, with a switch in the server config.

And it patches MFFS's projector twice more: its field selection, which ran on a background thread reading the world and the frequency grid while the server changed them (an error with a Fusion module whenever a player arrived), and its appetite for chunks, since the selection, the teardown, the Fusion module and the field blocks themselves each loaded unloaded chunks to look at them, so a field beyond the loaded area was loaded and dropped at least once a minute (a million dead block entities an hour on one server). Optional, on both sides, gated to exactly that build, with a switch each in the server config.

And it patches **Evolved Mekanism 1.3.0-fix3**'s Curios support, which registered Mekanism's HDPE Reinforced Elytra as a curio beside Elytra Slot, which already gives every elytra a curio capability; Forge refuses the second one, and the first capability lookup on that item (the creative inventory's search, a tooltip) crashed the game. Optional, on both sides, gated to exactly that build with Elytra Slot and Curios present; no switch, since the registration runs before the server config loads.

It also patches one method of **Minecraft** itself: a chunk's unload walks its block entity map live, and any mod's hook that changes that map meanwhile (a neighbour lookup, a block change) crashes the server with `ConcurrentModificationException`; the walk now runs over copies, names the block entity at fault once per type, and removes what was added during the unload. A switch in the server config restores vanilla's walk.

What each fix does is in `CHANGELOG.md`; the server settings that go with it are in `docs/CONFIG.md`; the checks are in `docs/TESTING.md`. The server log lists the fixes once loading is complete.

## Requirements

- Minecraft 1.20.1 with Forge 47.3.10 or newer (the network runs 47.4.23).
- Numina 2.3.13 and Modular Powersuits 2.3.13, on the client and on the server.
- Optional, client only: EMI 1.1.24+1.20.1+forge with JEI 15.74.0.234 for the EMI fixes (F-11 onward); they are skipped with any other EMI. Any JEI 15.74 build for the JEI fix (F-19); it is skipped with any other JEI.
- Nothing extra for the server-switch fixes (F-16, F-17); they matter on clients that switch servers through Velocity with Forge Client Reset Packet 0.3.2 and do nothing elsewhere.
- Optional, both sides: AdvancedAE 1.3.6-1.20.1 for the quantum armor fix (F-25); it is skipped with any other AdvancedAE.
- Optional, both sides: Gobber 2 2.8.9 for the dragon armour flight fix (F-27); it is skipped with any other Gobber.
- Optional, both sides: Compact Machines 6.0.3 for its fixes (F-28 to F-31; F-30 on the client only); they are skipped with any other Compact Machines.
- Optional, both sides: MFFS (Modular Force Field System) 5.1.29 for its fixes (F-34 to F-36, F-43, F-44); they are skipped with any other MFFS.
- Optional, both sides: Integrated Dynamics 1.31.5 with Cyclops Core and Common Capabilities for the dangling-part fixes (F-49, F-50); they are skipped with any other Integrated Dynamics or without its two libraries.
- Optional, both sides: Deep Resonance 1.20-5.0.6 for its fix (F-38); it is skipped with any other Deep Resonance.
- Optional, both sides: Iron Furnaces 4.1.8 for its fix (F-39); it is skipped with any other Iron Furnaces.
- Optional, both sides: Voltaic 1.20.1-1.2.2 together with Mekanism and Curios for the curio shielding fix (F-40); it is skipped with any other Voltaic or when either of the two is missing.
- Optional, both sides: Evolved Mekanism 1.3.0-fix3 together with Elytra Slot and Curios for the elytra registration fix (F-42); it is skipped with any other Evolved Mekanism or when either of the two is missing (without Elytra Slot there is nothing to fix).

## Build

```
./gradlew build
```

The jar is written to `build/libs/`. `./gradlew check` also runs `tools/check_lang.py` over the two shipped lang files (regenerate them with `tools/gen_lang.py <numina jar> <powersuits jar>` after a dependency bump). `./gradlew runGameTestServer` runs the headless tests (add `-PmixinVerbose` to see every injection Mixin applies); `./gradlew runServer` and `./gradlew runClient` start a dev server or client with both patched mods loaded; add `-PwithEmi` to any run to load EMI, JEI, Tinkers' Construct and Mantle as well (the exact pack files, from CurseMaven) for the EMI checks. `./gradlew runClient -PwithEmi -PquickPlay=<world>` opens a world from `run/saves` straight away, which is how the headless check reaches EMI's recipe reload. `-PemiProbe` on that run calls the EMI fixes' methods on EMI's real classes once loading is complete and logs one "BSP-Mod Fixes probe" line per check (the probe class lives in the gametest package and is not in the jar). `-PtitleProbe` on a client run closes the client by itself once the title screen has been up for a few seconds, so a headless run that only wants the startup log ends on its own. `-PwithAae` on any run loads AdvancedAE, AE2, GuideME and GeckoLib (the exact pack files), so the quantum armor GameTests hit a dressed player through the real mod; without it they check the pure logic and the gate's skip. `-PskipFixes=<mixin class names, comma-separated>` switches those mixins off for a run (the startup report lists their fixes as skipped), which is how a test shows the patched mod's own behaviour: `./gradlew runGameTestServer -PwithAae -PskipFixes=AaeDamageAbsorptionMixin` runs the quantum armor hit against AdvancedAE's own handler. `-PwithGobber` on any run loads Gobber 2 (the exact pack file), so the dragon armour GameTest ticks a dressed player through the real item and counts the abilities packets; `-PwithGobber -PskipFixes=GobberDragonFlightMixin` shows Gobber's own four a tick. `-PwithCm` on any run loads Compact Machines (the exact pack file), so its GameTest calls the mod's real chunk-mode code and counts the saves it makes; `-PwithCm -PskipFixes=CmTunnelSaveMixin,CmChunkloadSaveMixin` shows the mod's own one save a call. `./gradlew runClient -PwithCm -PpreviewProbe -PquickPlay=cmtest` opens the real room preview thirty times on a dev client by right-clicking a machine with an empty hand, so each comes through F-31 (one through a window resize), counts the OpenGL objects alive before, around one preview and after, and logs them with what the fix released; add `-PskipFixes=CmPreviewCleanupMixin` for Compact Machines' own behaviour. The save must be one kept for Compact Machines runs (`run/saves/cmtest`, a copy of `emitest`). A `-PwithCm` server or GameTest run keeps its own world folder, `run/world_cm`: Compact Machines' room dimension is written into the world's `level.dat`, and a world that has it does not load without the mod. `-PwithBallistix` on a run loads Voltaic, Electrodynamics, Nuclear Science, Ballistix and MFFS (the exact pack files, never compiled against), so the blast GameTests spawn real Ballistix blasts far from anything and log what keeps chunks loaded afterwards (the level's tickets by type, its loaded chunk count and Forge's saved ticket store, before the blast, as it starts, when it ends and a minute later); without it those tests say so and pass. Such a run keeps its own world folder too, `run/world_ballistix`, since the blasts tear up and generate terrain. `-PwithMffs` on any run loads MFFS (the exact pack file), so its GameTest places a real projector and runs the real sponge module against water, Fortron and a waterlogged slab inside its field; `-PwithMffs -PskipFixes=MffsSpongeMixin` shows MFFS's own pass, which builds the interior point set. The same run stands a powered projector forty-eight chunks away with a field reaching unloaded chunks and counts the chunk loads beyond its ticket, the blocks placed and the thread of each selection; `-PwithMffs -PskipFixes=MffsSelectionThreadMixin,MffsLoadedFieldMixin,MffsFusionProjectMixin,MffsFieldBlockLoadMixin` shows MFFS loading every chunk the field touches. `./gradlew runClient -PwithMffs -PfieldProbe -PquickPlay=emitest` builds a real camouflaged, glowing force field on a dev client, teleports the player away until its chunks have left the client and back, and logs the data requests the client sent on MFFS's channel while the field's blocks loaded again, the ticks until every block had its light and camouflage, and what the client's light engine and model data say; `-PskipFixes=MffsForceFieldSyncMixin` on the same run shows MFFS's own request per block. `-PwithDr` on any run loads Deep Resonance, McJtyLib and RFTools Base (the exact pack files), so the F-38 GameTest posts a real place event with no entity for an obsidian block through Deep Resonance's real handler; `-PwithDr -PskipFixes=DeepResonancePlaceEventMixin` shows Deep Resonance's own `NullPointerException`. `-PwithIf` on any run loads Iron Furnaces (the exact pack file), so the F-39 GameTest loads a real furnace-list provider and a mock player's capability twice from a duplicated tag; `-PwithIf -PskipFixes=IronFurnacesListLoadMixin` shows Iron Furnaces' own append. `-PwithHazmat` on any run loads Voltaic, Electrodynamics, Nuclear Science, Mekanism, Curios, Evolved Mekanism and IgleeLib (the exact pack files), so the F-40 GameTest doses a mock player wearing the real Portable Hazmat Suit through Voltaic's real recipient; `-PwithHazmat -PskipFixes=VoltaicCurioShieldingMixin` shows Voltaic's own armour-only shielding. `-PwithElytra` on any run loads that Hazmat set plus Elytra Slot and Caelus (the exact pack files), so the F-42 GameTest looks the real HDPE Reinforced Elytra's curio capability up through Forge's real attach event; `-PwithElytra -PskipFixes=EvolvedMekanismElytraCurioMixin` shows Forge's own `Duplicate Capability Key` refusal.
